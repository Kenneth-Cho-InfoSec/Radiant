## Physical tablet coverage

Samsung SM-X218U, Android 16/API 36, `arm64-v8a`: the current `0.1.0-debug` APK (target SDK 37) was reinstalled with `adb install -r` and cold-launched. The current build was manually inspected in expanded landscape (1280x800 dp) and compact portrait (800x1280 dp). Landscape showed Browser and Playlist with navigation rail; Channel Rack opened over the workspace. Portrait showed compact bottom navigation; Piano Roll filled the editor with note lanes and velocity controls. Auto-rotation settings were restored after the portrait check. This adds responsive-layout evidence on real ARM64 hardware; it does not establish broad gesture usability. The earlier short AAudio speaker-output transport check passed at 48 kHz with a reported 1,920-frame block. Physical audio latency, underruns, sustained playback, recording, Bluetooth/USB routing, and thermal behavior remain unverified. Screenshots and exact instrumentation output are listed in `docs/test-results.md`.

Latest physical run (2026-11-07): reinstalled the current debug APK with `adb install -r`, launched `com.radiant.daw.debug/com.radiant.daw.RadiantActivity`, and manually inspected the app in portrait and landscape on the SM-X218U. The screenshots show the Playlist workspace and Channel Rack in landscape, and compact navigation plus Piano Roll in portrait. This pass did not run instrumentation or exercise recording/audio. Current-build screenshots: `artifacts/radiant-samsung-sm-x218u-current-build-landscape.png`, `artifacts/radiant-samsung-sm-x218u-current-build-channel-rack-landscape.png`, `artifacts/radiant-samsung-sm-x218u-current-build-portrait.png`, and `artifacts/radiant-samsung-sm-x218u-current-build-piano-roll-portrait.png`.

The complete instrumentation suite passed on API 29 `Radiant_API29_Phone` and API 36 `Radiant_Tablet_API36`: 7 tests, 0 failures/errors on each AVD. It covers JUCE host/layout lifecycle, version-specific microphone permission and foreground-service handling, background playback after Home, and DocumentsUI CreateDocument/OpenDocument save/load for both `.lynx` and `.radiant`. Full XML reports are saved as `artifacts/radiant-instrumentation-api29.xml` and `artifacts/radiant-instrumentation-api36-tablet.xml`. The microphone tests verify permission/service wiring only; neither emulator validated recorded audio samples.

The debug APK contains separate ARM64 and x86_64 native libraries. The API 36 AVD executes only its x86_64 library; ARM64 is compile-verified only. The working AVD can be started with `emulator -avd Radiant_Tablet_API36 -no-snapshot -no-audio -gpu host -feature -Vulkan` (gfxstream). Emulator audio is only for functional checks; its observed 4,800-frame buffer at 48 kHz is not a physical latency, USB MIDI, Bluetooth, thermal, or battery measurement.

Before claiming VM acceleration, run the installed emulator's `-accel-check`. For each meaningful build, use `adb install -r app/build/outputs/apk/debug/app-debug.apk`, launch `com.radiant.daw.debug/com.radiant.daw.RadiantActivity`, capture logcat, and record screenshots or an explicit reason a check could not be exercised. On this host set `JAVA_HOME=$JAVA_HOME`, `ANDROID_HOME=$ANDROID_HOME`, and `ANDROID_SDK_ROOT=$ANDROID_HOME` for Gradle.
